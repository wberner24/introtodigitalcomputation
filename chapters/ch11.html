Chapter 11 · Unit 4: Networks

Network Architecture & Communication

⬡

A network is more than cables and protocols — it is an architecture. Devices are organized into roles: some provide services, others consume them. Switches and routers are arranged in tiers so traffic flows efficiently and policy is enforced at the right boundaries. Firewalls, VLANs, and NAT shape which devices can reach which resources. This chapter builds the mental model of how a real organizational network is designed and why each piece exists.

Client/Server Architecture

The dominant communication model in enterprise computing is client/server architecture. The idea is simple: one device, the server, provides a specific service and waits for requests. Other devices, the clients, initiate connections to consume that service. The server is always available; the client connects when it needs something.

Client/Server Architecture — a network model in which a dedicated server provides a service and clients initiate requests to consume it. The server listens; the client always goes first.

The "server" is a role, not necessarily dedicated hardware. Your laptop is acting as a client when it loads a web page. That same laptop could act as a server if it were running software that other devices connect to. In practice, enterprise servers are purpose-built machines with more RAM, faster storage, redundant power supplies, and server-grade operating systems — but the architectural pattern is about roles, not hardware.

Notice that the model stacks. A web application involves multiple client/server relationships: your browser is a client to the web server; the web server is itself a client to the database server behind it. The same machine plays different roles depending on which relationship you're examining.

Why enterprises rely on client/server: Centralization is the key advantage. Instead of storing files on 200 individual workstations, a file server holds everything in one place — backed up nightly, accessible from any authorized device, with permissions enforced centrally. Instead of managing accounts on every PC, Active Directory stores all user accounts on the domain controller — a new hire's account is created once and works everywhere. Patches and updates are applied to the server, and all clients benefit immediately. From an IT management perspective, a network of 200 workstations all pointing at the same server is far easier to maintain, secure, and audit than 200 independent machines each managing their own data and accounts.

Peer-to-Peer Architecture

In a peer-to-peer (P2P) architecture, there is no dedicated server. Every device is simultaneously client and server — it can request resources from others and provide resources in return. The network is decentralized: no single machine coordinates everything, and removing any one node doesn't bring down the system.

P2P excels at specific problems. BitTorrent is the classic example: when you download a file via torrent, you're downloading different pieces from dozens of users simultaneously while uploading the pieces you already have to others. The more people sharing a file, the faster everyone downloads — the opposite of a central server, which slows down as more clients pile on. Blockchain technologies like Bitcoin are also P2P at their core — thousands of nodes each hold a copy of the ledger, and there is no single authority that can be shut down or corrupted. Early voice-over-IP services like Skype used P2P to route calls directly between endpoints without a central call server.

P2P in the enterprise? Microsoft's Delivery Optimization feature (Windows 10/11) uses a quiet P2P approach: workstations on the same network share Windows Update packages with each other, reducing both the load on Microsoft's servers and the organization's internet bandwidth. Each PC is simultaneously downloading from and uploading to its neighbors. Active Directory still controls authentication and policy — only the software distribution is P2P.

Despite its advantages, P2P is rarely chosen for enterprise IT systems:

  • No central management point. You can't patch a "server" if there is no server. IT administrators need centralized control to push policy changes and respond to incidents.
  • Inconsistent availability. A file on a central server is always accessible. A file on a peer's laptop is unavailable when that laptop is powered off or off-site.
  • Security and compliance. Regulations governing sensitive data typically require demonstrable control over where data is stored and who can access it — something P2P makes difficult to audit or enforce.

How Enterprise Networks Are Structured

A network serving a large organization — a university, a corporation, a hospital — can't be a single flat segment where every device sees every other's traffic. Instead, enterprise networks are organized in a three-tier hierarchy: a core layer for backbone speed, a distribution layer for policy enforcement, and an access layer where end devices connect. This structure keeps traffic localized, makes troubleshooting straightforward, and allows the network to scale to thousands of devices without redesigning from scratch.

Use the explorer below to understand the role of each device type in this hierarchy.

The DMZ

Servers that must be reachable from the internet — a public web server, a mail relay, a VPN gateway — create a security problem. Putting them on the internal network gives them direct access to everything inside; putting them directly on the internet leaves them completely exposed. The solution is a DMZ (demilitarized zone): a separate network segment behind the perimeter firewall but isolated from the internal LAN. Firewall rules allow specific inbound traffic from the internet to reach DMZ servers, while blocking direct connections from the DMZ to the internal network. If a DMZ server is compromised, the attacker encounters another firewall before reaching internal systems.

NAT

IPv4's 4.3 billion addresses are not enough for a world with billions of internet-connected devices. Network Address Translation (NAT) solves this. When your home router or enterprise firewall connects to the internet, it has one public IP address assigned by the ISP. Every device behind it has a private address (the RFC 1918 ranges: 10.x.x.x, 172.16–31.x.x, 192.168.x.x) that is not routable on the public internet.

When an internal device sends a packet outbound, the NAT device rewrites the source IP from the private address to the public IP and records the mapping. When the reply arrives, it reverses the translation and delivers the packet to the correct internal device. The internet sees only one IP; internally, hundreds of devices communicate simultaneously through that single address. This is why every device on your home network has an address like 192.168.1.x, yet websites only see your ISP-assigned IP.

VLANs

By default, every port on a switch belongs to the same network segment — a device in accounting and a device in HR plugged into the same switch can communicate directly at Layer 2. A VLAN (Virtual Local Area Network) changes this: it logically divides a physical switch (or a set of interconnected switches) into isolated broadcast domains. A device on the Finance VLAN cannot send frames directly to a device on the Guest VLAN, even if they share the same physical switch. Traffic between VLANs must pass through a Layer 3 device — a router or distribution switch — where firewall rules and access control lists can inspect and control it.

A typical enterprise network has separate VLANs for employees, servers, guest Wi-Fi, IP phones (Voice VLAN), and network device management. Each VLAN behaves as its own logical network. VLANs are one of the most practical tools in enterprise networking: they give IT the ability to segment traffic for security and performance without running separate physical cable runs for every group.

Firewalls

A firewall inspects packets crossing a network boundary and allows or blocks each one based on an ordered rule set. Rules are evaluated top-to-bottom; the first match wins, and a default deny rule at the bottom blocks everything not explicitly permitted. Most enterprise firewalls use stateful inspection: they track active TCP and UDP sessions so that reply packets for connections initiated from inside are automatically allowed back in. This is why you can browse the web through a corporate firewall without the IT team needing to open inbound ports — the firewall knows the reply packets belong to an established outbound session.

The perimeter firewall at the internet edge is the most visible, but defense in depth requires more. Internal firewalls sit between the DMZ and the internal LAN, between the server VLAN and the employee VLAN, and at other sensitive boundaries. If an attacker penetrates one layer, additional firewalls limit how far they can move laterally through the organization.

VPN

A VPN (Virtual Private Network) creates an encrypted tunnel through the public internet. Traffic inside the tunnel is encrypted — anyone intercepting packets in transit sees only ciphertext. Two configurations are common in enterprise environments:

  • Remote access VPN: An employee working from home runs a VPN client that establishes an encrypted tunnel to the company's VPN gateway. From a networking perspective, the laptop appears to be physically on the corporate LAN — it can reach internal file servers, printers, and domain controllers as if sitting in the office.
  • Site-to-site VPN: Two office locations connect their networks permanently via a tunnel between two firewalls or routers. The Chicago and St. Louis offices share resources over the internet without exposing that traffic to interception.

Wireless Networking

Wireless (Wi-Fi, IEEE 802.11) operates at Layers 1 and 2 — it is a different physical medium, but the network layer and above work identically. A wireless access point bridges the Wi-Fi segment onto the wired Ethernet network. From the IP layer's perspective, a laptop connected over Wi-Fi and one connected over a cable are both just devices at the access layer.

The critical difference between home and enterprise wireless is authentication. At home, every device joins with the same shared passphrase (a pre-shared key, or PSK). Enterprise Wi-Fi uses 802.1X: each user authenticates with their own Active Directory username and password. The access point forwards credentials to a RADIUS server, which verifies them against Active Directory and signals the AP to admit or reject the device. IT can revoke network access for a specific user account without changing a password that every employee knows — and can see exactly which user is connected to which AP at any moment.

Where This Takes You

Chapter 12 (System Administration) shifts from architecture to operations — the day-to-day work of keeping these systems running. DNS and DHCP become concrete tasks: configuring zones, managing address pools, reading resolver logs. IP addressing becomes troubleshooting: ipconfig, ping, tracert, nslookup. The network architecture you've built a mental model of here becomes the infrastructure you have to maintain.

The networking course you'll take after this one starts where this unit leaves off — subnetting at depth, routing protocol configuration, spanning tree, 802.1X and RADIUS deployment, firewall rule writing, and network monitoring tools. The concepts in Chapters 10 and 11 are the foundation that makes those practical skills immediately sensible rather than a collection of disconnected commands.
